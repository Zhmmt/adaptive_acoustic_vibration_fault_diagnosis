# 技能包提炼与验证说明

## 技能包名称与定位

**AXI Overlay 接口核验与 DMA 数据验证技能包**，位于作品仓库 `skill/`。面向 AXI-Lite、固定帧 AXI-Stream 和 PYNQ Linux 软硬件协同项目，提供独立于具体业务算法的接口契约审计、定帧 DMA 接收、数据校验与故障定位方法。工程专用信息放在 JSON 契约与实例目录中，通用工具不固化 RS555 的地址与传感器逻辑。

## 问题来源与提炼过程

RS555 项目采用 PYNQ-Z2/Zynq-7000，PL 中包含 AXI GPIO、AXI IIC、simple S2MM AXI DMA、数字麦克风音频流、测速与显示接口，PS 端的整机工程通过 Vitis 裸机程序管理 ADXL345 与诊断状态。开发与验证中需要区分 HWH 接口是否正确、FPGA 是否真正加载、寄存器是否可以访问、流数据是否写入 DDR 以及原始数据如何解码。

本次问题有可检查的故障链：最初的 HWH 中 DMA `C_SG_LENGTH_WIDTH=14`，不足以表示 4096 个 32-bit 字组成的 16384 字节帧；通过在 Tcl 中设置长度位宽为 16 并重建硬件，PYNQ 端后续识别到 `buffer_max_size=65535`。在检查中还遇到 `ps7` 没有 `phys_addr`、AXI IIC 版本匹配警告及 Notebook 文件路径不一致等问题。由此形成三类可复用做法：预先核对硬件接口契约，采集时检查 DMA 完成状态及缓存，采集后使用标准数据格式和黄金样本核对文件内容。

## 具体实现

- **接口校验**：离线解析 HWH，按已核对的 JSON 检查实例名、地址区间和 IP 参数；PYNQ 环境下先以 `download=False` 检查元数据，再在电气安全条件下验证 MMIO。
- **DMA 检查**：以缓冲区字节数为单位核对长度寄存器上限、帧末 TLAST 规则以及 simple S2MM 的通道配置；保存 DMASR、接收长度和原始数据文件。可迁移脚本包含超时与 RX reset 的防护逻辑，实际板端复测仍需根据 DMA/驱动版本进行。
- **数据参考**：对 DDR 中小端打包的双路有符号 16-bit 音频进行 CSV/WAV 转换；使用确定性黄金样本检查正负号与通道顺序，使用 SHA-256 与长度比对实际捕获文件。
- **排障清单**：每项记录触发条件、源码/日志证据、修正步骤与失效边界；不把潜在风险当成已经重现的实测故障。

## 已验证结果

在 **PYNQ-Z2、PYNQ 2.7.0、Python 3.8.2** 环境，原始 Jupyter Notebook 记录：7 个关键 AXI IP 地址一致，Overlay 下载成功并读取状态寄存器，音频状态值连续变化；在修正 DMA 长度配置后，simple S2MM 报告 `DMASR=0x1002`、完成 16384 字节数据接收。保存的原始文件包含 4096 个 32-bit 字，4094 个非零字。离线对该文件独立重算，得到双通道 A/B 的平均值约 -81.74/-75.10，交流分量 RMS 约 20.63/19.65，相关系数约 0.97662，说明该样本有明显负向偏置，不能作为音质合格证据。

工具单元测试涵盖接口缺失、地址重叠、DMA 14/16 bit 边界、PCM 符号扩展和真实数据文件一致性等。所有具体数据和可核查原件见 `skill/docs/validation.md`、`skill/validation/pynq_z2/` 与 `skill/configs/source_evidence.json`。

## 适用边界与复用方式

更换题目和板卡时，应使用目标工程导出的新 HWH/BIT，审核并重建接口契约，核实 AXI-Stream 数据格式与 DMA 帧长；不得沿用 RS555 的地址、GPIO 控制位和电机安全假设。PYNQ Linux 与独立 Vitis 裸机是不同的主机软件环境，本次板端结果仅覆盖 PYNQ 所运行的验证路径。尚未提供跨板卡实测、音频保真度标定、整机异常识别性能或新版 Vitis 程序全功能验收的数据，报告不填入推测的性能/正确率指标。

比赛要求的完整工程、时序和资源报告、设计报告及实际交互协作原始记录，应按对应章节另行提交；本技能包只提供已经核查的技术方法与样例证据，不替代上述独立材料。
