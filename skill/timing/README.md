# 时序闭环优化工作流

适用：已具备可综合 RTL、已定义目标时钟、Vivado 可执行实现的项目。条件：固定器件与频率；不通过虚假 false_path、多周期例外或降低目标时钟换取正 WNS。

**步骤**：保存基线 `report_timing_summary`、`report_utilization`、`report_timing -max_paths 20` → 查看最差路径的起止寄存器、组合深度与布线占比 → 修改单个 RTL 瓶颈 → 流水线有效信号对齐和黄金参考仿真 → 重新综合与 route → 导出资源、时序、DRC → 将新路径加入下一轮清单。WNS>=0、TNS=0、WHS>=0 仅表示现有约束覆盖下的内部时序满足检查。

| 现场现象 | 分析与改进 | 案例结果 |
| --- | --- | --- |
| FIR 31 抽头顺序乘加 | 注册乘积并用平衡加法树流水化 | WNS -39.029 → -5.261 ns |
| LCD 每像素重复整数除法 | 帧级 BCD 预计算 | -5.261 → -4.843 ns |
| Tach 每窗口常量乘除 | 20 脉冲/转的准确整数特化 | -4.843 → -4.389 ns |
| DC Blocker 串联反馈算术 | 拆分 DSP 乘法/累加并登记有效脉冲 | -4.389 → +0.058 ns |

**后续观察**：最终最差路径为 `dc0/out_valid_reg → fir0/d_reg[25][6]/CE`，约 9.024 ns 为布线延迟，属于高扇出网络；不能把所有问题都归结为算术层数。延迟、资源利用和接口约束应并行核查。

**失效条件**：同步路径被误标异步、RTL 版本混淆、未形成真实 routed report、目标频率/约束被改动、最后 WNS 小于零时严禁标注通过。
